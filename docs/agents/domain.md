# Domain Docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant ADRs under `docs/adr/` when they exist.
- Proceed silently when these files do not exist.

## Use the glossary's vocabulary

When naming domain concepts in issues, refactor proposals, or tests, use the terms defined in `CONTEXT.md`. If a needed concept is missing, treat that as a domain-modeling gap rather than inventing a synonym.

## ADR conflicts

If a proposal contradicts an existing ADR, surface the conflict explicitly instead of silently overriding it.
